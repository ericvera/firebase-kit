# 01_01 Use betterbe's `reason` in validateSchema's `test` message

## Goal

Stop `validateSchema` printing the failing path twice for betterbe `test` failures. Today a failing `.test(...)` on field `phone` produces:

    Value of 'phone' failed custom validation (error: 'phone: invalid phone number').

After this task it produces:

    Value of 'phone' failed custom validation (error: 'invalid phone number').

Do this by reading betterbe 6.1.0's new `ValidationError.reason` field and raising firebase-kit-admin's betterbe ranges to `^6.1.0`.

## Files to modify/create

- `packages/firebase-kit-admin/src/validation/internal/validateSchema.ts`
- `packages/firebase-kit-admin/package.json`
- `yarn.lock` (regenerated by `yarn install`, not hand-edited)
- Test (does not count): `packages/firebase-kit-admin/src/validation/internal/validateSchema.test.ts`

## Background

- `validateSchema` (`packages/firebase-kit-admin/src/validation/internal/validateSchema.ts:11`) catches betterbe's `ValidationError` and rewrites it into a `FunctionsInvalidArgumentError` message. It builds `subject` (lines 29-36) as `Value of '<pathString>'` / `Key '<pathString>'` / `Value` / `Key`, so the path is already in the message.
- The `case 'test'` branch (lines 74-76) appends `error.message`. In betterbe 6, `message` is `<prefix><reason>`, where the prefix is `<pathString>: ` for value context, `key <pathString>: ` for key context, and empty when `pathString` is `''`. So the path shows up twice.
- betterbe 6.1.0 (published on npm) adds a read-only `reason` to `ValidationError`: the message without the `[key ]<pathString>: ` prefix, for every code. `message` is unchanged, and `reason === message` when there is no prefix. 6.0.0 does not have `reason`. The repo currently resolves 6.0.0 (`yarn.lock:2560-2562`).
- Only public caller: `validateSchemaAndTrim` (`packages/firebase-kit-admin/src/validation/validateSchemaAndTrim.ts:37`). Nothing else in `packages/` or any README uses the "custom validation" text.
- Owner decisions:
  - Keep the `(error: '...')` wrapper. Only the duplicated path goes.
  - Use `error.reason`. Do not strip a prefix from `error.message` yourself.
  - Raise betterbe to `^6.1.0` in both `peerDependencies` and `devDependencies` of `packages/firebase-kit-admin/package.json`, and update the lockfile. This narrows the floor within the same major, so it is not a breaking change. It ships as a `fix:` (patch) with no `BREAKING CHANGE:` footer.
- Test pattern to follow: `validateSchema.test.ts:24-32` (`await expect(validateSchema(...)).rejects.toThrowErrorMatchingInlineSnapshot(...)`).

## Implementation details

1. In `packages/firebase-kit-admin/package.json`, change `"betterbe": "^6.0.0"` to `"betterbe": "^6.1.0"` in both `peerDependencies` and `devDependencies`.
2. From the repo root (`/Users/eric/Code/firebase-kit`), run `yarn install` so `yarn.lock` resolves `betterbe@npm:^6.1.0` to 6.1.x. Confirm `node_modules/betterbe/dist/ValidationError.d.ts` declares `reason`.
3. In `validateSchema.ts`, change line 75 to:
   `message = \`${subject} failed custom validation (error: '${error.reason}').\``
   Change nothing else in the switch.
4. Add `it(...)` cases to `validateSchema.test.ts`, each asserting with `rejects.toThrowErrorMatchingInlineSnapshot`. Build schemas with betterbe's `object`, `string` and `record`. A test function has the signature `(value, report) => void`, and it fails by calling `report({ message: '<reason>' })`.
   - Value path: `object({ phone: string({ test: (_v, report) => report({ message: 'invalid phone number' }) }) })` with `{ phone: 'x' }`. Expected: `[Error: Value of 'phone' failed custom validation (error: 'invalid phone number').]`
   - Nested path: `object({ a: object({ b: string({ test: ... 'bad' }) }) })` with `{ a: { b: 'x' } }`. Expected: `[Error: Value of 'a.b' failed custom validation (error: 'bad').]`
   - Record key: `object({ m: record(string({ test: ... 'badkey' }), string()) })` with `{ m: { k: 'v' } }`. Expected: `[Error: Key 'm.k' failed custom validation (error: 'badkey').]`
   - Root-level test: `object({ name: string() }, { test: (_v, report) => report({ message: 'rootbad' }) })` with `{ name: 'x' }`. Expected: `[Error: Value failed custom validation (error: 'rootbad').]`
