# Task 1.4: Move the `getsetdel` range to 3

## Goal

Replace the `getsetdel` peer and dev ranges in `firebase-kit-client` with
`^3.0.0`, update the README lines that quote them, and delete the paragraph that
documents the old v2 pin — while leaving all test infrastructure untouched.

This is a deliberately minimal task. Adopting what `getsetdel` 3 ships is task
1.5.

## Requirements addressed

`goals.md` → "Major upgrades (decision 1b)", the `getsetdel` row and its
blast-radius item 3; plus the `getsetdel` lines of "Documentation".

## Background

`firebase-kit` is a Yarn 4 monorepo (`packageManager: yarn@4.18.0`) publishing
`firebase-kit-protocol`, `firebase-kit-client`, and `firebase-kit-admin` from
`packages/`. Tests are Vitest, colocated as `src/<name>.test.ts`, with
`mockReset: true`. The repo extends `@tsconfig/strictest`.

**Tasks 1.1, 1.2, and 1.3 already landed:** five in-range floors moved,
`firestore-snapshot-utils` was merged into `firebase-kit-admin` (and removed as a
dependency), and `firebase-admin` went to `^14.2.0`. None of them touched
`firebase-kit-client`'s getsetdel wiring.

### What `getsetdel` 3 breaks

`getMany` now resolves to `(T | undefined)[]` instead of `T[]`. Absent keys have
always resolved to `undefined`; the old declaration was simply wrong, and
`idb-keyval` 6.3.0 corrected its own type to match.

**Blast radius is type-surface only, and this task needs no code change.**
`getMany` appears in exactly one place in the repo — re-exported from
`packages/firebase-kit-client/src/__mocks__/getsetdel/index.ts:18` — and its
result is never consumed, so no call site needs to start handling `undefined`.

The runtime is otherwise near-identical between v2 and v3. Diffing the published
tarballs, the `dist` differences are `getMany.d.ts`, `queryInventory.d.ts`,
comment-only changes in `setMany.js` / `setMeta.js`, the new `dist/testing/`
directory, and roughly 28 compiled test files (`clear.test.js`,
`createStore.test.js`, …) that v3 ships inside `dist`. Those are inert for this
repo — the client vitest project's `root` is `src` and it excludes
`**/node_modules/**` — but they are worth knowing about before task 1.5 adds
`server.deps.inline: ['getsetdel']`.

The existing local factory at
`packages/firebase-kit-client/src/testing/createGetSetDelMock.ts` destructures
`queryInventory` out of the module (`const { queryInventory: _queryInventory,
...rest } = actual`) with a comment saying getsetdel does not export the type its
signature needs. v3 still exports `queryInventory` itself, so **that destructure
still compiles** — only the query *type* became exported, which is what makes
task 1.5's cleanup possible. This task therefore ends green with the existing
factory, the existing `__mocks__` shim, and `fake-indexeddb` all unchanged.

## Implementation details

1. Change `getsetdel` from `^2.0.0` to `^3.0.0` in **both** the
   `peerDependencies` and `devDependencies` blocks of
   `packages/firebase-kit-client/package.json`. **Replace** the range — do not
   write `^2.0.0 || ^3.0.0`.

2. Run `yarn install` from the repo root. Do not pass `--immutable`.

3. Run `yarn build`, `yarn lint`, `yarn test:unit`. Run `yarn test:emulator` too
   to confirm the admin package is unaffected (the client package has no emulator
   tests).

4. Update `packages/firebase-kit-client/README.md`:
   - `:57` — the install snippet `npm install firebase 'getsetdel@^2.0.0'`
     becomes `npm install firebase 'getsetdel@^3.0.0'`.
   - `:64` — `- **`getsetdel`** (`^2.0.0`)` becomes `(`^3.0.0`)`. Leave the
     "IndexedDB store the cached Firestore reads persist through" sentence.
   - `:67` — **delete the entire paragraph** beginning "**`getsetdel` must be
     major 2.**" and running through "...the conflict fires at install time no
     matter which entry points you go on to import." It documents the v2 pin as
     deliberate and says the range "will move when it is ported" — this task is
     that port, so the paragraph is now false. Delete it and its surrounding
     blank line. Do not rewrite it into a v3 equivalent; there is no longer a
     conflict to explain.

  `peerDependencies`. Updating only the dev copy leaves the published contract
  stale.
- **Do not adopt `getsetdel/testing` or `getsetdel/testing/idb-keyval` in this
  task.** They are in scope for the work overall, but they are task 1.5. Leave
  `src/testing/createGetSetDelMock.ts`, `src/testing/createGetSetDelMock.test.ts`,
  `src/__mocks__/getsetdel/index.ts`, `src/__test__/setup/vi.setup.ts`,
  `vitest.config.ts`, and the `fake-indexeddb` dev dependency exactly as they
  are. This task must end green on the existing infrastructure.
- **Do not touch the client `./testing` entry point name.** The rename to
  `./mocks` is task 1.5.
- The repo runs `lint-staged` on commit, so committing reformats and re-lints.
